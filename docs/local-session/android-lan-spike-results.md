# Local Session Android LAN spike results

**Recorded:** 2026-10-05

**Purpose:** isolated, unauthenticated, unencrypted, synthetic-text transport feasibility instrument. The bounded transport milestone was subsequently demonstrated on two physical Android phones; this report still makes no authentication, confidentiality, or production-security claim.

3. **Implementation commits:** `3134d66` (`feat(experiment): add isolated local session Android spike`), `1fd257d` (`fix(experiment): enforce frame and storage bounds`), `ef01152` (`fix(experiment): complete standalone app resources`).
4. **Module:** `android/experiments/local-session-spike/`; opt-in with `-PlocalSessionExperiment=true`.
5. **Application ID:** `com.k3ncrypt.experiment.localsession`, distinct from `com.k3ncrypt.app`.
6. **Production modules changed:** none. `android/settings.gradle.kts` only adds the experiment behind the opt-in property; production Android manifests and sources are unchanged.
7. **Dependency isolation:** no project dependency or production package imports. Debug runtime graph is Kotlin stdlib `2.0.21` plus annotations `13.0` and Android framework APIs. JUnit `4.13.2` is test-only and is already used by other repository Android modules.
8. **Storage/app sandbox isolation:** distinct package UID/sandbox; no shared user ID, provider, exported service/receiver, IPC bridge, Room, SharedPreferences, files, Keystore, or persisted session state. Backup and device-transfer rules exclude app data. This is package isolation, not an OS-compromise guarantee.
9. **Permissions:** `INTERNET` for TCP sockets and `ACCESS_NETWORK_STATE` for selected-Wi-Fi/capability inspection. Both are normal install-time permissions for target 35; no runtime prompt is required. No production permission changed. Android 16 local-network restrictions are opt-in; Android 17 requires `ACCESS_LOCAL_NETWORK` for apps targeting API 37 or higher. See [Android local-network permission guidance](https://developer.android.com/privacy-and-security/local-network-permission).
10. **NSD implementation:** foreground Android `NsdManager` DNS-SD registration and discovery using `_k3nlsx._tcp.`. Discovery hints are untrusted; connecting is a separate user action.
11. **Advertisement contents:** instance name `lsx-` plus 16 random bytes rendered as 32 lowercase hex characters; dynamic TCP port; no TXT records or user/device identity fields. API 33+ uses network-scoped NSD. API 26–32 NSD lacks that scope here, so the app rejects a profile with active cellular/VPN networks; it does not claim perfect interface isolation on those releases.
12. **TCP framing:** 8-byte preamble `K3NLSX1\n`; each frame has a 4-byte big-endian length followed by type and body. The length excludes the prefix; complete on-wire frame is capped at 512 bytes (declared type+body cap 508). Types: HELLO=1, ACCEPT=2, TEXT=3, CLOSE=4. TEXT contains a big-endian 32-bit sequence and strict printable ASCII. Context carries two random 16-byte experiment values; neither is an identity or authenticator.
13. **Resource limits:** one active peer; 512-byte complete frame; 256-byte synthetic text; 8-frame/4096-byte outbound queue; 16 pending inbound UI deliveries; three bounded I/O workers with an eight-task queue and one bounded sender with an eight-task queue; 5-second resolve/connect/preamble/HELLO limits; 30-second acceptance wait; 2-second frame read timeout; 60-second idle timeout; 60-second discovery window; 120-second advertisement; 10-minute session maximum; six connection attempts per minute; discovery callback rate cap; 100 text messages per side with at least 100 ms between sends.
14. **Lifecycle/fencing:** stop/background/destroy unregisters NSD, closes listener and socket, cancels deadlines and pending acceptance, clears queues and in-memory values. Each async operation carries a generation; old generations cannot update the current state. Per-session workers/queues are bounded.
15. **Restart semantics:** state is created in memory and not restored. New process/controller starts INACTIVE. Teardown clears messages and ephemeral context. Unit tests cover recreation and a start–stop–start stale callback; emulator cold launch showed INACTIVE.
16. **UI:** persistent warning says “UNAUTHENTICATED AND UNENCRYPTED,” synthetic-only and not normal K3NCRYPT; the status remains unauthenticated after transport acceptance. Visible states include inactive, advertising, discovering, peer found, waiting acceptance, connecting, connected, disconnected, and failed. UI also says Internet required: No, session temporary/memory-only, transport NSD + bounded experimental TCP, and relay not used.
17. **Synthetic messages:** `PING-A`, `PING-B`, `HELLO-LOCAL-1`, `HELLO-LOCAL-2`; no free-text field. Received text is displayed in memory and cleared on teardown.
18. **Unit tests:** PASS, 20 tests total (8 bounds/state, 12 protocol), zero failures. Covers requested framing, malformed lengths/frames/types, max text/frame, queue bounds, state transitions, teardown, generation fencing including restart, expiration, recreation, and duplicate hint handling.
