# Firebase F1b Phase A — bounded, process-local reliability

Base: `9aec504f74f2981f80b61347b9584a35c823ef2d`. Branch: `codex/backend-firebase-f1b`.

Implemented without schema/index changes:

- Five-second application deadline per provider invocation (or remaining wake lifetime, if shorter). Firebase Admin cannot cancel a send through its public send API. Timed-out operations therefore keep their per-registration slot until the underlying operation settles. Maximum 32 live jobs per dispatcher, including timed-out sends, and 32 concurrent recipient-resolution tasks. No replacement requests can accumulate behind a permanently unresolved SDK call. This can saturate wake capacity during an outage; encrypted mail remains independent.
- Only observed provider acceptance installs the 30-second success throttle, bounded to 512 entries. Concurrent wakes for the same registration coalesce while work is pending. No durable retry or restart claim is made.
- Three application attempts maximum for allowlisted transient SDK failures, with 250/500ms pauses and one unchanged event ID/expiry. Recheck current registration, active device/identity/epoch, feature gate and expiry before retries. SDK-internal network retries are distinct from these application attempt counters. Quota/rate-limit failures are not retried inside the 60-second event; no arbitrary unknown/payload/authentication failure retires a token.
- Only `messaging/registration-token-not-registered` and `messaging/invalid-registration-token` are definitive invalid-token responses. Cleanup compares the exact observed token hash, token, owner/device/identity, epoch and update timestamp using one conditional delete. Registration's post-write epoch-race cleanup uses the same conditional operation. Missing/changed registrations do not redirect the old wake to a replacement token.
- Aggregate, saturating process counters: attempted, accepted, rejected, expired, failed, timedOut, retired, coalesced, throttled and busy. `privateWakeCounters(db)` returns a copy and creates no public endpoint or automatic logs. Attempts count application provider invocations; acceptance is observed within the deadline, never device delivery. Late provider completion after timeout remains ambiguous and does not become a delivery ACK or a second counter update.
- Generic payload allowlist unchanged. FCM remains disabled by default; no SDK initialization/credentials/network use on the disabled path. No mailbox state/FIFO/ACK behavior, Android source, calls, cryptography, UI, protocol, schema or production settings changed.

Limitations deliberately reserved for Phase B: no durable dispatch state, no crash recovery or cross-process throttle/dispatch lease; existing registration rotation is not transactionally serialized across instances; exact same-token re-registration within the same timestamp requires a durable revision for a stronger ABA fence. Recipient resolution still requires an unexpired prekey publication. Expired/missing prekeys are not accepted as authorization. SDK sends may physically finish after the application deadline; recipient event expiry still applies. No physical notification-delivery result is claimed.
